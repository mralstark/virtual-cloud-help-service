# Pilot operability review — 2026-09-07

Scope: startup, database stores, Timeweb integration, deployment path, dependency
currency and repository navigation. VPN path validation requires the actual
server/client and source-network evidence.

## Confirmed corrections

- Registration could fail on PostgreSQL because `jsonb_build_object` parameters
  lacked types (SQLSTATE 42P18). Explicit text/timestamptz casts fix inference;
  a real pgx integration test covers registration.
- Repeated revocation returned 404 after the first success. Retries now return
  the original record without duplicate audit events, including concurrent calls.
- Startup checked only SELECT. It now verifies every required write permission.
- Comma-separated PostgreSQL privilege lists mean ANY. SQL security checks now
  test each required permission individually.
- Standard PostgreSQL lacked runtime grants; migration 000004 adds the same
  minimum permissions as the Supabase deployment.
- Telemetry cleanup retains its bounded batch and lock timeout. It is
  opportunistic and needs scheduled cleanup if idle-time deletion is required.
  Row-lock skipping would require extra UPDATE privileges; the pilot keeps the
  smaller permission set.
- SSH blocked the port forwarding needed for the private API. The template now
  permits local forwards only to 127.0.0.1:8080 and :9100.
- Timeweb API responses can include root/VNC passwords. Preflight decodes only
  safe inventory fields and never includes raw response bodies in errors.
- Issuer process locking is scoped to its state directory and rejects symlinks,
  non-regular files and permissive lock files. Linux regression tests cover these
  cases. CI also exercises development initialization, readiness and graceful
  restart with a persistent manifest sequence.

## Method choices

Keep one Linux service and PostgreSQL. No additional broker, orchestrator, custom
VPN client or cryptographic scheme is needed for this pilot. Official AmneziaVPN
owns VPN installation and profile lifecycle; signed discovery remains separate.

Use maintained AmneziaWG and Xray REALITY as UDP/TCP options; record installed
versions from the official client. The Amnezia release API reports 5.0.1.5
(2026-08-21). Xray reports v26.3.27 as latest non-prerelease; newer tags through
v26.7.28 are marked prerelease. A larger version number alone does not justify
replacing deployed components. The artifact lock remains laboratory-only.

Go moves to the official 1.27.1 patch with verified archive/container digests.
Direct application dependencies showed no newer versions in the Go module proxy
during this review. CI reads go.mod and adds a dedicated PostgreSQL test job.

Use direct PostgreSQL or the IPv4 session pooler for this persistent service.
Transaction pooling would require a different session/prepared-statement contract
without a practical benefit at the pilot's five-connection scale.

IP rotation cannot make a destination belong to an allowlist. It also needs client
distribution, connection draining, capacity and billing decisions. Keep it an
operator recovery action until field evidence justifies automation. Encryption
strength and a successful handshake do not prove a complete transfer succeeds.

## Remaining operational inputs

Final server ID/IP and API token; SSH key/verified host; installed VPN ports and
client profile; real catalog/discovery values; protected signing material;
dedicated database login and admin token when metadata is enabled. An API token
alone cannot supply all of these or complete client acceptance tests.
